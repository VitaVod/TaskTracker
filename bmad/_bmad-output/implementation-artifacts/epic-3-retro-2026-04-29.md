# Epic 3 Retrospective: Progression Engine and Momentum Experience

Date: 2026-04-29
Epic: Epic 3
Status: Completed Retrospective
Stories: 5 planned, 5 marked done in sprint status

## Scope Reviewed

- Story 3.1: Build XP ledger and idempotent completion processing
- Story 3.2: Implement streak rule engine with timezone policy
- Story 3.3: Expose progress APIs for XP, streak, and trend snapshots
- Story 3.4: Build dashboard progress components and feedback UI
- Story 3.5: Implement momentum summary and historical progress view

## Executive Summary

Epic 3 delivered the full progression loop from deterministic write-path processing to user-visible momentum feedback. The team implemented replay-safe XP grants, timezone-aware streak computation, authenticated progress read APIs, and dashboard components for immediate reinforcement plus historical trend context.

The strongest outcome is end-to-end determinism: completion events, progression state, and UI updates are now built around server-authoritative, idempotent behavior with consistent contracts.

The main concern is quality-signal consistency across story artifacts and validation reporting. One pre-existing frontend test failure was explicitly carried during Story 3.2, and Story 3.4 notes include both drafting/ready-for-dev and implementation-complete language, which can weaken audit confidence.

## What Went Well

1. Deterministic progression baseline was implemented end-to-end
- Story 3.1 established XP ledger idempotency with SQL Server uniqueness constraints and replay-stable responses.
- Story 3.2 extended determinism into streak outcomes with explicit `continue/reset/restart` semantics and timezone projection.

2. API and frontend contracts stayed aligned
- Story 3.3 introduced `/api/v1/progress` endpoints with typed models and bounded trend windows.
- Stories 3.4 and 3.5 consumed those contracts directly without introducing parallel client-side progression logic.

3. UX quality improved for trust and accessibility
- Immediate post-completion reinforcement was added with XP and streak feedback updates.
- Momentum summary/history views were added with loading/empty/error states and non-color-only indicators.

4. Coverage and validation trend was generally positive
- Epic 3 stories recorded meaningful API and frontend test activity.
- Concurrency/idempotency and timezone edge behavior were explicitly tested rather than assumed.

## What Did Not Go Well

1. Validation consistency still has gaps
- Story 3.2 reports passing API tests but carries one pre-existing frontend failure.
- This creates ambiguity for "all-green" confidence at epic closure.

2. Artifact narrative consistency needs tightening
- Story 3.4 completion notes include both drafting/ready-for-dev and completed implementation statements.
- Mixed state language in done stories can reduce traceability confidence.

3. Some reliability concerns remain inherited from prior epics
- Earlier mention of completion-toggle flakiness (Epic 2 retro) implies continued need for stronger deterministic concurrency regression packs.

## Key Risks Going Into Epic 4

1. Regression risk in shared progression paths
- Leaderboard/read-model work will depend on XP/streak correctness. Any regression in idempotency or timezone handling can erode trust quickly.

2. Test-signal risk
- If known failures remain tolerated or under-tracked, release confidence for cross-feature changes declines.

3. Contract drift risk as read surfaces expand
- New public/shared leaderboard APIs increase pressure to keep error and payload contracts consistent across endpoints.

## Lessons Learned

1. Deterministic processing should remain a non-negotiable architecture rule
- Server-authoritative progression logic and replay-safe contracts prevented duplicate reward outcomes and UI divergence.

2. Timezone correctness must be treated as core behavior
- UTC storage with local-day projection is essential for user trust in streak continuity.

3. Story-close quality gates should include evidence quality checks
- Status should only be done when tests, file list, and completion narrative are coherent and contradiction-free.
